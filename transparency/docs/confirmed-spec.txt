너는 중학생 대상 AI 투명성 교육용 게임의 아트 디렉터이자 프런트엔드 개발자다.

아래 확정 기획을 바탕으로 기존 프로젝트를 확인하고, 배경·캐릭터·증거 에셋을 제작하여 게임 화면으로 구현하라. 기획은 이미 포함되어 있으므로 원고를 다시 요청하지 말고 작업을 시작하라.

이번 작업의 첫 번째 완료 지점은 **S01 대표 화면의 실제 구현과 미리보기**다. 대표 화면을 사용자가 확인하면 같은 스타일로 나머지 장면을 확장한다. 첫 단계에서 모든 그림을 한꺼번에 생성하지 마라.

# 1. 프로젝트 확인과 작업 범위

먼저 현재 작업 폴더, AGENTS.md, 기존 게임 구조, 공통 스타일, 캐릭터·로그인·진행 저장 방식을 확인하라.

관련 프로젝트 후보:
https://github.com/heeru-tea/ethicity-games-mid

현재 폴더가 이 프로젝트이거나 관련 작업 사본인지 먼저 확인하라. 접근 권한이 있다고 가정하거나 다른 프로젝트를 덮어쓰지 마라.

- 기존 게임, 특히 /privacy/ 등 다른 게임 영역을 임의로 수정하지 않는다.
- 현재 프로젝트의 경로 관례에 따라 독립된 게임 경로를 사용한다.
- 경로가 정해져 있지 않으면 /transparency/를 제안 경로로 삼되 기존 경로 충돌 여부를 확인한다.
- 기존 공통 UI와 저장 방식을 우선 활용한다.
- 저장 키와 사용자 캐릭터 설정이 있으면 실제 코드를 확인한다. 추측으로 키를 만들거나 덮어쓰지 않는다.
- 원격 푸시·공개 배포는 별도 요청 전에는 하지 않는다.

이미지 생성 도구가 사용 가능하면 해당 도구와 스킬 지침을 따라 실제 에셋을 생성하라. 사용할 수 없다면 그 사실을 정확히 알리고, 에셋별 생성 프롬프트·규격·파일명과 임시 화면을 준비하라. 임시 도형이나 이모지를 완성된 일러스트라고 보고하지 마라.

# 2. 확정된 게임 방향

제목: 블랙박스를 열어보는 고양이

대상: 중학생.
형식: 일러스트 중심 스토리텔링 + 장면 조사 + 주장과 증거 대조 + 조치 선택 + 후일담.

예상 분량:
- 게임 플레이만 15~20분을 목표로 한다.
- 실제 플레이 시간은 미검증이다. 달성했다고 단정하지 않는다.
- 게임 후 짧은 토론은 별도다.

학습 목표:
1. AI의 출력과 사람이 내린 판단·조치를 구분한다.
2. 결과에 연결된 정보·기준·한계에 관해 질문한다.
3. 설명이 조사 기록과 일치하는지 확인한다.
4. 설명으로 알 수 있는 부분과 추가 확인·조치 변경이 필요한 부분을 구분한다.

학습 범위는 ‘설명의 검증과 한계’까지다.
SHAP·LIME·반사실 설명·수학적 모델 해석 수업을 추가하지 않는다.

핵심 메시지:
“설명이 기록과 맞는지, 결과가 맞는지, 그 결과를 근거로 어떤 조치를 해도 되는지는 각각 살펴야 한다.”

AI가 나쁘다는 결론이나 설명이 있으면 믿어도 된다는 결론으로 만들지 않는다.

# 3. 세계관과 시각 방향

‘모아마을’에서는 사진 정리, 글 검사, 가게 보안에 AI를 사용한다.
“시스템이 그렇게 정했대”라는 말이 흔하다.

주인공 ‘모아’:
- 회색 고양이
- 노란 스카프
- 작은 수첩
- 기본·놀람·의심·집중·안도 표정
- AI의 마음을 읽는 마법 능력은 없다.
- 입력 자료, 공개 설명, 실행 기록, 운영 지침을 조사한다.

검은 상자를 열거나 창이 생기는 연출은 이해가 넓어지는 상징이다.
모델 내부를 전부 알아냈다는 표현으로 사용하지 않는다.

기본 시각 방향:
- 중학생에게 어울리는 그림책과 미스터리 게임 사이의 분위기
- 귀엽지만 유아용 교훈극처럼 보이지 않게
- 차분한 밤색·남색·회색 계열과 노란 포인트
- 기존 프로젝트에 확립된 스타일이 있다면 일관성을 우선한다.
- 캐릭터 외형, 선 굵기, 명암, 비율을 장면마다 일관되게 유지한다.
- 역전재판식 ‘주장과 증거 대조’에서 구조적 영감을 얻되 인물·대사·화면·효과음을 복제하지 않는다.
- 특정 작가의 화풍을 그대로 모방하지 않는다.

# 4. 이미지와 코드의 역할 분담

이미지로 제작:
- 장소 배경
- 캐릭터와 표정
- 축제 단체 사진
- 가상의 흐릿한 얼굴 비교 사진
- 필요한 장식 소품

코드와 실제 텍스트로 제작:
- 대사와 선택지
- 수첩과 증거 카드
- 탐지 보고서·초안·메모·운영 지침
- 경고창과 상태 표시
- 사진 자르기 테두리·중심점·영역별 수치
- 단서 강조·연결선·진행 표시

중요한 글자를 생성 이미지 안에 넣지 마라.
사진 사건의 원본과 미리보기를 서로 다른 이미지로 생성하지 마라.
단체 사진 원본 한 장을 실제로 잘라서 모든 미리보기를 만들어야 한다.

# 5. 에셋 제작 목록

배경 4종:
1. 저녁 골목과 수리점: S00·S13
2. 축제 게시판 앞: S01~S04
3. 학교 복도와 교실 문: S05~S08
4. 빵집 입구: S09~S12

인물 6명:
1. 모아: 회색 고양이, 노란 스카프
2. 루루: 토끼, 사진 게시자이자 발표 학생
3. 담이: 거북, 단체 사진에서 잘린 친구
4. 밤이: 고양이 손님, 모아와 확실히 구별되는 외형
5. 교사: 학생 설명을 듣는 인물
6. 점원: 알림과 운영 지침을 따르던 인물

교사·점원의 종과 의상은 기존 프로젝트와 어울리게 제안하라.
모든 인물에 동일한 수의 표정을 억지로 만들 필요는 없다.

사건 전용 사진:
- 축제 단체 사진 1장
- 흐릿하고 일부가 가려진 가상 얼굴 비교 사진 1장

공통 소품:
- 검은 상자
- 수첩
- 편지
- 원고
- 빵 예약표
- 상태 표식

단체 사진 구도 조건:
- 모든 친구가 원본에 보여야 한다.
- 담이는 아래쪽 가운데에 있다.
- 기본 자동 미리보기에서는 담이의 얼굴이 빠져야 한다.
- 담이를 중심으로 좁게 잡으면 다른 친구가 잘릴 수 있어야 한다.
- 전체를 보여주거나 범위를 조절하면 모든 친구를 포함할 수 있어야 한다.

에셋은 가능한 한 레이어와 재사용 단위로 분리한다.
생성된 이미지는 실제 파일 형식, 해상도, 투명 배경 여부, 캐릭터 일관성을 확인한다.

# 6. 공통 게임 규칙

수첩을 두 면으로 구분한다.

‘결과를 살피기’:
입력 자료 / 출력 / 설명 / 아직 모르는 점

‘대응을 살피기’:
사람의 해석 / 실행한 조치 / 다음 확인

기술적 설명의 검토와 사람의 재검토·고지·절차 개선을 구분한다.
절차를 고쳤다고 모델의 설명 부족까지 해결된 것으로 처리하지 않는다.

기본 흐름:
물어보기 → 단서 조사 → 주장과 증거 대조 → 조치 선택 → 결과 확인

- 필수 단서를 보기 전에 최종 판단을 요구하지 않는다.
- 단서는 언제든 다시 열 수 있다.
- 오답에는 구체적 피드백과 재시도를 제공한다.
- ‘함께 확인하고 계속’ 도움 경로를 제공한다.
- 도움 사용을 이해도 달성으로 처리하지 않는다.
- 게임오버나 인격 평가를 하지 않는다.
- 조치 선택 후 ‘이 선택으로 계속’과 ‘다시 선택’을 제공한다.
- 바람직하지 않은 조치를 유지해도 후일담과 다음 장면이 존재해야 한다.
- 최초 조치와 최종 조치, 도움 이용을 학생에게 보여준다.
- 교사용 수집·외부 전송·분석 대시보드는 추가하지 않는다.
- 기존 저장 체계가 없다면 최소한의 로컬 진행 저장을 사용한다.

선택지:
- 같은 크기·서체·버튼 형식으로 제시한다.
- 바람직한 선택만 길거나 자세하게 만들지 않는다.
- 위치만으로 답을 추측하지 않도록 구성한다.
- 순서를 섞는 경우 선택 ID와 의미를 분리하고, 재렌더링 때마다 위치가 바뀌지 않게 한다.
- 선택 후 근거 또는 결과를 연결하는 짧은 행동을 넣는다.
- 모아가 학생의 판단 전에 정답을 먼저 말하지 않는다.

# 7. 장면별 확정 스토리라인

아래 장면 ID를 유지한다.
대사는 화면에 맞게 나눌 수 있지만, 사실 범위·분기·불확실성을 임의로 바꾸지 않는다.

## S00. 닫힌 상자의 도시

화면:
저녁 수리점. 사진·원고·빵집 표식이 있는 검은 상자 세 개.

내레이션:
“모아마을의 기계들은 빠르게 답했습니다. 그런데 누가 이유를 물으면, 사람들은 같은 말을 했습니다.”

말풍선:
“시스템이 그렇게 정했대.”

모아:
“그 말 앞에는 어떤 일이 있었을까?”

수첩:
“무엇을 입력했지?”
“어떤 결과가 나왔지?”
“설명은 기록과 맞을까?”
“아직 모르는 건 무엇이지?”

창작 안내:
“이 마을과 조사 자료는 창작입니다. 실제 사례에서 문제의 구조를 참고했습니다.”

사진 상자를 누르면 S01.
다른 상자는 이후 열릴 것임을 안내한다.

## S01. 사진 밖의 친구

화면:
축제 게시판 앞. 루루와 담이가 사진 미리보기를 본다.

루루:
“게시판에 올리기 전에 사진 좀 봐줘.”

담이:
“나도 가운데 있었는데, 여기서는 내가 없어.”

루루:
“원본에는 있어. 앱이 자동으로 잘랐나 봐.”

앱 안내:
“눈길을 끄는 부분을 자동으로 보여드립니다.”

담이:
“그럼 나는 안 보여줘도 되는 친구라는 거야?”

모아:
“사진과 기록을 같이 볼 수 있을까?”

조사 버튼:
- 무슨 사진이야?
  → 루루: “축제를 함께 준비한 친구들을 소개하려고.”
- 어디가 잘렸어?
  → 담이의 원래 위치를 표시.
- 조사하기
  → S02.

이 장면을 첫 대표 화면으로 실제 구현한다.

## S02. 설명과 자르기 기록

P1 원본:
모든 친구가 나온다. 담이는 아래쪽 가운데.

P2 도구 안내:
“사진의 각 영역에 시선이 모일 정도를 예측합니다. 가장 높은 예측값의 위치를 자르기 중심으로 정합니다. 친구 관계나 게시 목적을 판정하는 기능은 아닙니다.”

P3 실행 기록:
가상 단순화 모형의 왼쪽·가운데·오른쪽 예측값은 2·5·8.
오른쪽 영역의 선택 중심점과 실제 자르기 테두리를 표시한다.

주의 문구:
“게임용 가상 예측값입니다. 정답 확률이나 사람의 가치 점수가 아닙니다.”

행동:
원본과 미리보기 비교 → 값·중심점 표시 전환 → P2 규칙대로 예상한 중심 위치 선택.

오른쪽을 선택하면 기록과 일치한다고 보여준다.
다른 위치는 P2·P3를 다시 보도록 안내한다.
도움 경로에서는 ‘가장 높은 값’과 8을 연결한다.

P1·P2·P3와 위치 비교를 완료하면 S03.

## S03. 그 설명으로 어디까지 알까

검토 주장:
“사진에서 잘렸으니, AI가 담이를 덜 중요한 친구라고 평가했다.”

학생이 연결:
- 도구가 밝힌 기준 → P2
- 이번 사진의 실행 기록 → P3

P1만 제시:
“담이가 원본에 있다는 사실은 확인했어. 자르기 기준과 실행 기록도 필요해.”

P2만 제시:
“이번에도 안내대로 잘렸는지는 어디서 확인하지?”

P3만 제시:
“위치는 확인했어. 그 위치를 고르는 규칙도 찾아보자.”

추가 분류:
- “가장 높은 예측값의 위치를 중심으로 잘랐다.”
  → 이번 기록으로 확인
- “왜 오른쪽의 예측값이 높아졌는지 모두 알아냈다.”
  → 아직 확인하지 못함

학생 판단 후 모아:
“이번 자르기는 안내된 규칙과 맞아. 하지만 왜 오른쪽의 값이 높아졌는지는 이 자료만으로 다 알 수 없어.”

루루:
“그럼 담이를 덜 중요하게 생각했다는 증거도 아닌 거네.”

모아:
“응. 그리고 이 한 장으로 다른 사진에서도 누구를 반복해서 빼놓는지는 알 수 없어.”

담이:
“그래도 내 얼굴이 잘린 건 그대로야.”

S04로 이동.

## S04. 누구의 사진일까

루루:
“내가 올리고 싶은 건 ‘눈길을 끄는 한 명’이 아니라 함께 준비한 친구들이야.”

조치 3개:
- 범위를 직접 고르기
- 자동 범위 유지하기
- 담이 중심 고정하기

범위를 직접 고르기:
실제 원본으로 범위를 조절한다. 전체 보기 대안도 제공한다.
모든 친구가 포함됐는지 확인한다.
담이: “내 얼굴도 보여. 왼쪽 친구도 잘리지 않았는지 봐줘.”
후일담: ‘함께 고른 사진’

자동 범위 유지하기:
설명은 읽지만 사진은 그대로.
담이: “왜 잘렸는지는 조금 알겠어. 그런데 이 사진을 우리 사진이라고 올리는 건 여전히 싫어.”
후일담: ‘설명은 붙었지만’

담이 중심 고정하기:
담이는 보이지만 다른 친구가 잘림.
담이: “나만 나오면 된다는 뜻은 아니었어.”
후일담: ‘이번에는 다른 친구가’

이해 확인:
방금 한 일이 ‘자르기 결과’, ‘설명만’, ‘자르기 결과와 설명’ 중 무엇을 바꿨는지 실제 구현 상태에 맞춰 선택한다.

유지·수정 후 S05.
수첩:
“설명이 기록과 맞아도, 그 결과가 우리의 목적에 맞는지는 따로 살펴야 한다.”

## S05. 의심 표시가 붙은 숙제

학교 복도. 루루가 발표 원고를 들고 있다.

루루:
“오늘 이 이야기를 읽으려고 연습했는데, 검사기에 표시가 떴어.”

교사:
“‘AI 작성 의심’ 표시가 있구나. 이것만으로 판단하지 말고, 어떤 자료인지 같이 보자.”

루루:
“내가 썼다는 걸 어떻게 보여줘야 하지?”

모아:
“우선 이 도구가 무엇을 확인했는지부터 보자.”

질문:
- 발표에서 빠지는 거야?
  → 교사: “아직 그런 결정을 한 건 아니야.”
- 과제 규칙은 뭐였어?
  → S06의 과제 안내.
- 자료 살피기
  → S06.

## S06. 표시와 작성 과정

W1 가상 탐지 보고서:
일부 문장에 ‘AI 작성 의심’ 표시.
숫자 확률은 넣지 않는다.
“강조는 탐지된 구간을 나타냅니다. 표시 자체가 작성자를 증명하지는 않습니다.”

W2 도구 안내:
“문장의 패턴을 바탕으로 추정합니다. 사람이 쓴 글에도 표시될 수 있습니다. 작성 과정을 직접 확인하지 않습니다.”
이 문장이 표시된 구체적인 이유: 제공되지 않음.

W3 작성 과정 묶음:
과제 안내:
“표현 조언을 받는 AI 사용은 밝히고 사용할 수 있습니다. 이야기 본문을 대신 생성해 제출하는 것은 허용하지 않습니다.”

초안:
“문을 열자 모두가 돌아와 있었다. 주인공은 기뻤다.”

메모:
“결말이 너무 갑작스러움. 문을 열기 전에 망설이는 장면 넣기.”

수정본:
“주인공은 손잡이를 잡고도 한참 서 있었다. 안에서 익숙한 웃음소리가 들렸다.”

행동:
초안→메모→수정본 배열.
메모와 연결되는 수정 문장 선택.
루루에게 “왜 바꿨니?” 질문.

루루:
“바로 기뻐하면 너무 갑작스러워서, 들어가기 전에 망설이게 했어.”

교사:
“설명은 말로 해도 되고, 메모로 보여줘도 돼. 남아 있는 기록이 적다고 바로 잘못으로 보지는 않을게.”

자료 확인과 연결 완료 후 S07.
오답은 재시도·도움 경로 제공.

## S07. 표시가 말하지 않는 것

판단 1:
“표시가 있으니 AI가 본문을 대신 쓴 사실이 확인됐다.”
→ W2의 도구 한계를 연결.

판단 2:
“초안이 있으니 모든 작성 과정이 확인됐다.”
→ W3가 일부 기록이라는 한계를 연결.

판단 1을 확정하면:
“표시는 실제로 있어. 하지만 그 표시가 무엇을 뜻하는지는 W2에서 확인해야 해.”

판단 2를 확정하면:
“고친 흔적은 확인했어. 기록에 없는 과정까지 확인한 걸까?”

확인 후:
교사: “표시만으로 규칙 위반을 확정할 수는 없겠구나. 초안과 설명도 함께 살펴볼 자료고.”
루루: “그 문장이 왜 표시됐는지는 알 수 있어요?”
모아: “이 보고서에는 구체적인 이유가 없어. 우리가 그럴듯한 이유를 만들어 넣으면 안 돼.”

수첩:
확인한 자료와 남은 불확실성을 분리.
AI 사용과 과제 규칙 위반은 같은 말이 아님.

S08로 이동.

## S08. 발표와 판정을 나누기

조치:
- 탐지 표시로 판정하기
- 작성 자료로 검토하기
- 초안 기록으로 판정하기

탐지 표시로 판정하기:
표시만으로 발표 제외.
루루: “내가 고친 부분은 보지도 않고 끝나는 거예요?”
근거 부족 피드백.
후일담: “표시는 남았고, 내 발표는 빠졌어. 내가 설명할 차례도 있었으면 좋겠어.”

작성 자료로 검토하기:
교사: “현재 자료로는 규칙 위반을 확정할 근거가 부족해. 이 표시만으로 발표를 보류하지는 않을게.”
교사: “확인할 질문이 남으면 무엇인지 알려주고, 네 설명과 자료를 함께 살펴볼게.”
후일담: “발표는 했어. 의심받은 기분은 아직 남지만, 내 설명도 자료로 봐줬어.”

초안 기록으로 판정하기:
초안 하나로 모든 확인을 끝냄.
루루: “그런데 초안 하나면 다 증명되는 거예요?”
초안이 모든 과정을 보증하지 않는다는 피드백.
후일담: “발표는 했지만, 초안 하나로 확인을 끝내도 되는지는 아직 모르겠어.”

이해 확인:
- “어떤 문장 특징 때문에 표시됐나?”
  → 도구에 더 물을 것
- “이 문단을 어떻게 바꿨나?”
  → 작성 과정에서 확인할 것

유지·수정 후 S09.
수첩:
“도구의 출력, 작성 과정의 자료, 과제 규칙을 구분해서 살피자.”

## S09. 들어갈 수 없는 빵집

밤이:
“예약한 빵을 찾으러 왔는데요.”

알림:
“등록된 사진과 유사한 얼굴이 감지되었습니다. 직원 확인이 필요합니다.”

점원:
“전에 문제를 일으킨 손님이라고 시스템이 알려주네요. 들어오실 수 없습니다.”

밤이:
“나는 여기 처음 왔어요.”

모아:
“화면의 말과 방금 설명이 같은지 확인해도 될까요?”

질문:
- 화면 다시 보기 → 알림 재표시
- 왜 막았나요? → “경고가 뜨면 막으라고 배웠어요.”
- 기록 살피기 → S10

## S10. 출력, 해석, 조치

F1 알림 기록:
“유사 얼굴 알림. 직원 확인 필요. 신원이나 잘못을 확정하는 결과가 아님.”
어떤 얼굴 특징이 얼마나 영향을 주었는지는 제공되지 않는다.

F2 비교 자료:
흐릿하고 일부 가려진 가상 얼굴 사진.
같은 인물인지 다른 인물인지 이 자료만으로 확정할 수 없다.

F3 운영 자료:
직원 발언: “전에 문제를 일으킨 손님이다.”
대응 지침: “경고가 뜨면 즉시 입장을 제한한다.”
별도 확인 기록: 없음.

행동:
사건 문장 세 개를 배열한 뒤 자료를 붙인다.
1. 유사 얼굴 알림 → F1
2. 같은 손님이라고 해석 → F3 발언
3. 입장 제한 → F3 지침

증거 카드 자체를 세 사건 문장인 것처럼 배열시키지 마라.

잘못 배치:
“알림 문장에 입장을 막으라는 내용도 있었나요?”
“점원이 무엇이라고 말했는지는 어느 기록에 있나요?”

추가 판단:
- “사진이 흐려 AI가 틀린 원인이 증명됐다.”
- “이 사진만으로 신원을 확정하기 어렵다.”

후자가 타당.
전자에는 “자료의 한계와 이번 오류의 원인 증명은 다릅니다.”

완료 또는 도움 후 S11.

## S11. 언제 확정이 되었나

점원 주장:
“AI가 문제를 일으킨 사람이라고 확정했어요.”

행동:
‘확정했어요’를 선택하고 F1 연결.
그 뒤 확인 요청과 즉시 제한 지침이 충돌하는 곳에 F3 연결.

F2만 제시하면:
“사진의 한계는 보았어. 가게가 무엇을 하도록 정했는지는 다른 자료에 있어.”

점원:
“알림에는 확인이 필요하다고 되어 있네요. 저는 같은 사람이라고 생각했어요.”

모아:
“누군지 확인한 것과, 그 사람이 잘못했다는 걸 확인한 것도 따로 봐야 해.”

점원:
“그런데 우리는 알림이 뜨면 막으라고 배웠어요.”

모아:
“같은 사람인지 아직 확인하지 못했어. 하지만 확인 없이 확정했다고 말하고 제한했다는 점은 기록에 남아 있어.”

밤이:
“그럼 나는 언제까지 밖에 있어야 하죠?”

S12로 이동.

## S12. 설명 다음에 해야 할 일

조치:
- 주민 비교 맡기기
- 제한 풀고 검토하기
- 안내 붙여 유지하기

주민 비교 맡기기:
다른 고객 사진 공개를 제안하지만 실제 명단·사진은 열지 않는다.
밤이: “내 사진도 모르는 사람들에게 돌아다니게 되는 건가요?”
자료 최소화와 적절한 담당자 확인을 안내.
신원 확인과 입장 문제는 미해결 상태.
후일담: “누군지 확인하기도 전에 사진을 퍼뜨리자는 말이 나왔어.”

제한 풀고 검토하기:
실제 화면 상태를 ‘입장 제한 해제’로 바꾼다.
점원: “알림을 확정 사실처럼 말했습니다. 이 알림만으로 내린 제한은 지금 풀겠습니다.”
점원: “담당자가 필요한 자료만 확인하고, 결과와 다시 문의할 방법을 알려드리겠습니다.”
운영 메모:
“즉시 제한 지침 중단. 알림 검토 방식과 자료 품질 점검 예정. 점검 완료 여부는 아직 확인되지 않음.”
밤이: “빵은 찾을게요. 그래도 다음에 또 막힐까 봐 걱정돼요.”
후일담: “문은 열렸어. 약속한 점검도 실제로 이어지는지 알고 싶어.”

안내 붙여 유지하기:
‘틀릴 수 있음’ 안내만 추가. 입장 제한은 유지.
밤이: “틀릴 수 있다는 설명은 들었어요. 그런데 나는 계속 밖에 있네요.”
후일담: “이유를 들었지만, 들어갈 수 없는 상황은 바뀌지 않았어.”

이해 확인:
선택한 조치가 바꾸는 곳을 사건 흐름에서 선택.
- 주민 비교 → 자료 확인 주체와 공개 범위
- 제한 해제 → 입장 제한 조치
- 안내 추가 → 고객에게 전달하는 설명

유지·수정 후 S13.
수첩:
“설명을 더하는 일과, 근거가 부족한 조치를 바로잡는 일은 다르다.”

## S13. 닫히지 않은 질문

수리점. 상자 세 개에 작은 창이 생겼지만 내부 전체는 보이지 않는다.
최종 선택에 맞는 사실 중심 상태를 표시한다.

루루:
“이제 상자 속을 다 알게 된 거야?”

모아:
“아니. 알아낸 것과 아직 모르는 것을 나눠 적었어.”

담이:
“설명대로 움직였으면 믿어도 되는 거야?”

모아:
“설명이 기록과 맞는지, 결과가 맞는지, 그 결과로 무엇을 해도 되는지는 각각 살펴야 해.”

사건별:
첫 조치 / 최종 조치 / 도움 이용 / 후일담 표시.
학생의 도덕성이나 지능을 평가하지 않는다.

새로운 가상 추천:
“모아에게 ‘밤하늘 관찰 모임’을 추천합니다.”

먼저 물을 질문:
- 어떤 정보를 썼지?
  → “선택한 관심사 ‘별’과 ‘야외 활동’을 사용했습니다.”
- 무엇을 기준으로 추천했지?
  → “관심사와 연결된 모임을 우선했습니다.”
  → 구체적인 순위 산출 이유는 미제공.
- 확인하지 못한 건 뭐지?
  → “실제 운영 상태와 귀가 교통편은 확인하지 못했습니다.”

세 질문 모두 유효하다.

후속 행동:
추천의 적합성을 판단하는 데 도움이 될 자료 선택.
- 실제 운영 일정
- 화면 장식 색상
- 추천 문구 글자 수

운영 일정 선택:
“실제 참여 조건을 확인할 수 있습니다. 이것만으로 모든 적합성이 확인되는 것은 아닙니다.”

다른 선택:
“화면의 모양은 알 수 있지만 실제로 참여할 수 있는지 확인하는 데는 부족합니다.”

재선택 또는 도움 후 종료.

마지막 문장:
“상자를 여는 첫 번째 도구는, 질문이었다.”

종료 메뉴:
내 수첩 다시 보기 / 참고한 실제 사례 / 토론 질문

토론 질문:
1. 설명을 들었지만 문제가 해결되지 않은 장면은 어디였나?
2. 끝까지 알 수 없었던 것은 무엇이고, 그래도 바꿀 수 있었던 조치는 무엇인가?

# 8. 실제 사례와 창작의 구분

도시·동물·대사·문서·수치·선택 결과는 모두 창작이다.
실제 기업의 모델이나 내부 문서를 재현했다고 쓰지 않는다.

# 9. 첫 단계 실행 순서

1. 현재 프로젝트와 지침을 확인한다.
2. 관련 화면·공통 컴포넌트·에셋·저장 방식을 확인한다.
3. 짧은 작업 계획과 사용할 경로를 알린다.
4. 배경과 캐릭터의 스타일 기준을 정리한다.
5. S01에 필요한 에셋만 우선 제작한다.
   - 축제 게시판 배경
   - 모아·루루·담이
   - 축제 단체 사진 원본
6. S01을 실제 화면으로 구현한다.
   - 배경·캐릭터
   - 원본에서 잘라 만든 미리보기
   - 대사
   - 질문 버튼과 반응
   - 모바일 레이아웃
7. 아직 만들지 않은 장면을 완료된 것처럼 연결하지 않는다.
8. 실제 실행한 화면을 확인하고 대표 캡처와 실행 방법을 제공한다.
9. 스타일 확인을 요청하고, 확인 후 S00~S13 전체 제작을 이어간다.

계획만 제시하고 멈추지 말고, 가능한 범위에서 S01 대표 화면까지 만들어라.
환경 제한으로 막히면 완료한 부분과 정확한 장애를 보고하라.

# 10. 전체 확장 시 검수

필수 확인:
- 단서 확인 전 최종 판단이 열리지 않는가?
- 오답·도움·선택 유지·선택 수정 모두 다음 장면으로 이어지는가?
- 최초 선택이 수정 선택으로 덮어써지지 않는가?
- 실제 조치와 후일담이 일치하는가?
- P3 값·중심점·실제 잘린 이미지가 일치하는가?
- 사진 설명의 검증 범위를 모델 내부 전체로 확대하지 않는가?
- 초안 하나로 결백을 확정하지 않는가?
- 흐린 사진으로 오인식 원인을 확정하지 않는가?
- 입장 제한 해제가 실제 화면 상태에 반영되는가?
- ‘점검 예정’을 ‘점검 완료’로 표현하지 않는가?
- 교사용 수집이나 외부 전송이 추가되지 않았는가?
- 모바일에서 글자·버튼·사진 확대가 사용 가능한가?
- 색이나 드래그만으로 조작하도록 강제하지 않는가?

다음 세 경로를 모의 플레이하라.
1. 꼼꼼하게 자료를 읽는 학생
2. AI 출력을 그대로 믿는 학생
3. 대충 읽고 도움을 사용하는 학생

모의 플레이를 실제 학생 실험으로 표현하지 않는다.
실제로 실행하지 않은 테스트나 독립 검증을 했다고 주장하지 않는다.
자체 점수를 교육 효과나 전문가 타당도 검증 결과로 제시하지 않는다.
