# 미리 알리기 변주 — 사건 4·5 ‘잘못된 안내문 고치기’ 설계안 (2026-11-12, 미구현)

수정 요청 10번: “미리 알리기가 5번 모두 같은 카드 틀이라 뒤로 갈수록 패턴 맞추기가 된다. 사건 4·5는 카드 고르기 대신 짧은 안내문 직접 쓰기나, 잘못된 안내문 고치기로 바꿔 보자.”

이번에는 **구현하지 않았다.** 엔진의 안내문 상태·수첩·보고서·저장·브라우저 검사(flow-browser의 미리 알리기 왕복)까지 함께 바뀌는 일이라, 같은 날 다른 13건과 묶어 검증 없이 넣는 것보다 설계를 먼저 확인받는 쪽을 골랐다. 사건 4·5의 미리 알리기는 지금도 카드 고르기 그대로다.

## 고른 방식: 잘못된 안내문 고치기 (직접 쓰기는 하지 않음)

- 직접 쓰기는 자동으로 맞고 틀림을 가릴 수 없고(교사 수집도 없다), 생각 정리 서술 칸과 겹친다.
- 고치기는 카드 자료(`cases.*.notice.cards`)·판정(`noticeCheck`)·보고서(`noticeSummary`)를 그대로 쓴다. 달라지는 것은 **출발점**이다: 빈 안내문에서 고르는 대신, 누군가 먼저 쓴 **틀린 초안**에서 시작해 뺄 문장을 빼고 빠진 문장을 넣는다. 하는 일이 ‘고르기’에서 ‘진단하기’로 바뀐다.

## 초안(처음 붙어 있는 카드)

| 사건 | 초안에 든 카드 | 고쳐야 할 것 |
|---|---|---|
| 4 구청 공개 페이지 | `camp-role`(꼭) · `camp-never`(약속) · `camp-everyone`(부딪침) | 약속·부딪침 빼기, `camp-office`·`camp-appeal` 넣기 — 직접 확인에서 찾은 빈 칸 둘(담당 부서·이의 신청)과 같은 자리 |
| 5 냥스타 게시물 글 | `share-same`(약속) · `share-spell`(있으면 좋음) | 약속 빼기, `share-ai`·`share-real` 넣기. 부딪침 카드는 초안에 없다(사건 4와 틀린 모양이 다르게) |

## 자료 모양 (story.js)

```js
notice:{ mode:'fix',                       // 없으면 지금의 카드 고르기
  title:'구청이 올린 공개 페이지 초안, 어디를 고칠까?',     // 사건 5: '루루가 쓴 게시물 글 초안, 어디를 고칠까?'
  paper:'구청 공개 페이지', lines:[],
  draftLabel:'처음 초안',                   // 왼쪽 종이 머리말(붙이기 전)
  cards:[…그대로…] }
// 공통 문장(D.notice.fix): task '초안에서 뺄 문장은 빼고, 빠진 문장은 넣어 봐. 다 고쳤으면 ‘고친 안내문 붙이기’를 눌러.'
//  post '고친 안내문 붙이기', inDraft '초안에 있던 문장', added '새로 넣음', removed '뺐음', same '초안과 같아. 고칠 곳을 찾아봐.'
```

초안 카드 목록은 판정과 같은 곳에 둔다: engine `noticeDrafts={camp:['camp-role','camp-never','camp-everyone'],share:['share-same','share-spell']}`.

## 엔진

- 새 행동은 없다. `notice-pick`(넣기·빼기 토글)·`notice-post`·`noticeCheck` 그대로.
- **초안 넣기**: `next`로 미리 알리기 장면에 처음 들어올 때, `noticeDrafts[k]`가 있고 `picked`가 비어 있고 `posted===null`이면 `picked=초안`. (`consistent`의 ‘미리 알리기 전에는 picked가 비어 있다’ 검사는 그대로 통과한다 — 들어온 뒤에 채우므로.)
- `notice-post`는 fix 사건에서 **초안과 같은 채로는 붙일 수 없게** 한다(`picked`가 초안과 같은 집합이면 무시). 화면은 버튼을 끄고 ‘초안과 같아. 고칠 곳을 찾아봐.’를 보인다. 이것이 없으면 아무것도 안 고치고 한 번 눌러 넘어갈 수 있다(틀린 채 넘어가는 것은 지금처럼 허용하되, 손은 한 번 대게).
- 판정·‘다 맞음’ 기준은 그대로(꼭 필요 모두 + 부딪침·약속 없음).

## 저장

- 칸 모양은 그대로(`notices[k]={picked,posted}`), version 7 그대로 둘 수 있다.
- 이미 미리 알리기 장면을 지난 저장: `posted`가 배열이면 그대로(카드로 붙인 안내문), `legacy`면 그대로.
- 미리 알리기 장면에 서 있고 아직 아무것도 안 고른 저장(`picked` 빔·`posted` null): 화면을 그릴 때 초안이 비어 있으면 **restore에서 초안을 채운다**(version 7 안에서 `furthest>=sceneOf(k,'notice') && picked.length===0 && posted===null`). 이미 카드를 고르던 저장(`picked` 있음)은 그 고른 것을 그대로 두고, 화면은 ‘초안에 있던 문장’ 표시만 붙인다.
- 검사: 위 세 경우 + version 6 → 7 사슬 + 162개 조합(초안 때문에 ‘꼭 필요 카드를 차례로 누르기’가 `camp-role`을 **빼게** 되므로, 검사 도우미는 ‘원하는 집합과 다른 카드만 누르기’로 바꿔야 한다 — `combinations.test`, `ui.test`의 `stateAt`, `render-snapshot`의 `notice()`, flow-browser `notice()`, motion-browser `BUILD`, title-browser `stateAt`).

## 화면 (ui/notice.js)

- 머리: 새 제목. 고정 한 줄(모아 / 사건 5는 이용자용 한 줄)은 그대로.
- 왼쪽 종이: 붙이기 전에는 ‘처음 초안’(초안 카드 문장), 붙인 뒤에는 지금처럼 붙인 안내문.
- 오른쪽: 카드 목록은 같은 토글 버튼(`aria-pressed` = 지금 안내문에 들어 있음)이지만, 초안에 있던 카드에는 글자 표시 ‘초안에 있던 문장’, 상태 글자는 ‘넣음/뺐음/새로 넣음’. 버튼 이름 ‘고친 안내문 붙이기’.
- 붙인 뒤 피드백·전체 판정·혼자 규칙(사건 5는 판정 태그만, 부딪침 이유는 보임)은 지금 그대로.
- 휴대폰 높이: 카드 수가 같아 지금 높이(구청 6장·냥스타 6장)에서 표시 글자 한 줄씩만 는다 — flow-browser의 ‘붙이기 전 높이 ≤ 화면의 1.05배’를 다시 재야 한다.

## 수첩·보고서

- 그대로(`noticeSummary`: 붙인 카드, 빠진 꼭 필요 카드, 판정). 더할 것 하나: fix 사건에는 ‘초안에서 뺀 문장 N개 · 새로 넣은 문장 N개’ 한 줄(초안과 `posted`의 차이로 계산).

## 검수가 필요한 새 문장

제목 둘, 과제 문장, 버튼 이름, 표시 글자 넷(‘초안에 있던 문장’·‘새로 넣음’·‘뺐음’·‘처음 초안’), ‘초안과 같아. 고칠 곳을 찾아봐.’ — 카드 문장 12장은 그대로.

## 결정이 필요한 것

1. 고치기 방식으로 갈지, 직접 쓰기(자동 판정 없음)를 원하는지.
2. 초안을 한 글자도 안 고치고는 붙일 수 없게 할지(위 설계) — 지금 원칙 ‘틀려도 한 번 붙이면 넘어간다’와 조금 다르다.
3. 사건 4 초안이 직접 확인의 빈 칸(담당 부서·이의 신청)을 되풀이하는 것이 좋은지(연결) 나쁜지(답이 쉬움).
