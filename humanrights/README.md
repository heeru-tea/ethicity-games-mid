# AI 안면인식 심의위원회 — 인권보장 시뮬레이션 (`/humanrights/`)

중·고등학생이 **윤리시티 안전위원회 위원**이 되어 건물 출입·채용·치안 세 분야의 AI 안면인식 도입 안건을 심의하는 웹 게임입니다. 같은 기술이라도 쓰이는 곳과 조건에 따라 지켜지는 권리와 위협받는 권리가 달라지는 것을 정책 결과 시뮬레이터로 확인합니다.

> 핵심 질문: 정확도가 높다는 사실은 그 기술의 모든 활용 방식이 정당하다는 뜻일까?

- 대상: 중학생·고등학생 / 개인 플레이 후 교실 토론 / 약 25분 + 마무리 쓰기(목표치, 실측 전)
- 흐름: 위원회 소집 → 안건 3개(각 7단계) → 정책 가이드라인 → 반론 검토 → 개인 성찰 → 심의 보고서(PDF 저장)
- 안건마다: 사건 브리핑 → 데이터 분석 → **최초 판단(확정 후 변경 불가)** → 추가 정보 → 시민 인터뷰 → 정책 결과 시뮬레이터 → 최종 판단
- 선택지는 세 안건 모두 A. 도입한다 / B. 인권 보호 조건을 마련한 후 도입한다 / C. 도입하지 않는다
- 점수·등급·정답 판정이 없습니다. 계산 문항(8배, 100명)만 맞았는지 알려 주고, 두 번 틀리면 풀이를 보여 준 뒤 넘어갑니다.
- 서버·로그인·외부 API·분석 도구 없음. 게임 속 기관·인물·숫자는 수업용 허구입니다.

## 실행

정적 파일입니다. 공통 팩을 `../shared/`에서 불러오므로 **저장소 루트**를 정적 서버로 열고 `/humanrights/`에 접속합니다.

```bash
npx serve .            # 또는 python3 -m http.server — 저장소 루트에서
# → http://localhost:<포트>/humanrights/
```

`index.html`을 파일로 직접 열어도(`file://`) 실행됩니다(ES 모듈·fetch를 쓰지 않음). 브라우저가 저장을 막으면 메모리로만 진행하고 안내가 뜹니다.

- 주소 인자 `?rebuttal=safety|cost|majority`: 반론 검토의 반론을 교사가 고릅니다(기본값은 기본 반론). 메뉴의 ‘반론 검토에 쓸 반론(교사용)’으로도 바꿀 수 있습니다.

## 파일 구조

| 파일 | 역할 |

| `index.html` | 머리 막대(안건·진행 단계) · 본문 · 아래 고정 이전/다음 · 메뉴·확인 대화 상자 |
| `css/style.css` | 공통 팩 `common.css` 위의 게임 전용 스타일. 픽셀 글꼴은 제목·버튼에만, 긴 글·입력칸은 시스템 한글 글꼴. 375px 대응, 인쇄(PDF) 스타일 |
| `js/config.js` | 조정값 · 공통 팩 경로 · **역할별 캐릭터 배정(`CAST`)** · 안건별 배경(`SCENES`) |
| `js/stories.js` | **스토리 데이터** — 안건·자료·인터뷰·시뮬레이터 문장·반론·마무리 질문. 문장 수정은 이 파일만 |
| `js/engine.js` | 상태 엔진(진행 조건·최초 판단 잠금·계산 문항·시뮬레이터·일관성 점검·저장 복원). DOM을 모르는 순수 로직, Node에서도 동작 |
| `js/storage.js` | 저장 래퍼(localStorage 실패·손상 시 조용히 건너뜀) |
| `js/app.js` | 화면 그리기·입력 처리 |
| `tests/` | 검증 도구(게임 실행에는 쓰이지 않음) |

## 공통 에셋 팩 사용

`shared/ethicity-elementary-common-v1`(v1.0.0)을 **수정하지 않고** 그대로 씁니다.

- `runtime/common.css`의 색 토큰(`--ee-*`)·창(`ee-panel`·`ee-speech`)·버튼(`ee-button`·`ee-choice`)·배지
- `EthicityAssets`로 배경(`drawBackground`)·인물(`drawCharacter`)·대화 얼굴(`drawPortrait`)·효과음(`playSound`)
- 그림을 못 불러와도 글과 기능은 그대로 진행합니다.

| 화면 | 배경 | 등장 인물(임시 배정) |
|---|---|---|
| 위원회 소집 | AI 실습실 | 안내 로봇 = 심의 도우미 |
| 안건 1 출입 | 도서관 | 다온 = 도서관 이용 학생, 사서 = 도서관 운영 담당자 |
| 안건 2 채용 | 교실(시험장) | 교사 = 채용 담당자, 하늘 = 채용 지원자, 온유 = 인권 전문가 |
| 안건 3 치안 | 학교 중앙마당(중앙광장) | 새봄 = 실종자 가족, 지호 = 인권단체 활동가 |

공통 팩의 인물은 학생 5명·교사·사서·로봇뿐이라 **어른 역할(채용 지원자·인권 전문가·실종자 가족·활동가)을 학생 캐릭터로 임시 배정**했습니다. 팀에서 정하면 `js/config.js`의 `CAST`만 바꾸면 됩니다.

## 저장 키와 팀 공통 연동

| 키 | 읽기/쓰기 | 내용 |
|---|---|---|
| `ethicity.player` | **읽기만** | 별명(20자까지, `textContent`와 같은 방식으로 이스케이프해 표시). 없거나 손상되면 ‘위원’ |
| `ethicity.result.humanrights` | 보고서 화면 도달 시 쓰기 | `{"game":"humanrights","completed":true,"ending":null,"card":"AI 안면인식 심의위원회 · 출입 조건부 도입 · 채용 도입 · 치안 도입 안 함"}` |
| `ethicity.humanrights.progress.v1` | 이 게임 전용 | 진행 위치와 모든 답(자동 저장, 새로고침해도 이어짐) |
| `ethicity.humanrights.settings.v1` | 이 게임 전용 | 효과음 켬/끔(기본 꺼짐) |

- 메뉴의 ‘이 게임 기록 지우기’는 `progress`와 `result.humanrights`만 지웁니다. 공통 플레이어 정보와 다른 게임 키는 건드리지 않습니다.
- 학생이 쓴 글은 이 기기의 localStorage에만 남고 어디로도 보내지 않습니다. 제출이 필요하면 보고서를 PDF로 저장합니다.

## 정책 결과 시뮬레이터

학생이 A/B/C와 (B일 때) 보호 조치 7가지 중 원하는 것을 골라 결과를 비교합니다. 하나의 점수로 합치지 않습니다.

- 네 측면(효율·비용·인권 침해 위험·시민 신뢰)마다 **기대되는 효과**와 **남아 있는 위험**, 3칸 수준 표시(글자로도 표기)
- 보호되는 권리 / 제한될 위험이 있는 권리 / 해결되지 않은 문제 / 영향을 받는 시민
- 규칙(`engine.js` `simulate`): 안건마다 위험 목록(`stories.js` `sim.risks`)이 있고, 각 위험을 줄이는 보호 조치(`fixedBy`)가 정해져 있습니다. 고른 조치가 하나라도 닿으면 그 위험은 ‘줄어든 위험’으로 옮겨 가고, 닿지 않으면 남습니다. 줄어든 위험도 0이 되지 않는다는 안내가 항상 붙습니다.
- 수준: 인권 침해 위험은 남은 위험 수(0 낮음·1 중간·2 이상 높음), 시민 신뢰도 같은 수로(높아짐·나뉨·낮아짐), 효율은 처리를 느리게 하는 조치(`slows`)가 있으면 ‘좋아짐’, 없으면 ‘크게 좋아짐’, 비용은 비용이 드는 조치가 3개 이상이면 ‘많이 늘어남’. C안은 변화 없음·늘지 않음·새 위험 없음·그대로.
- 이 안건의 위험을 직접 줄이지 않는 조치를 고르면 ‘해결되지 않은 문제’에 따로 알립니다.

## 마무리 단계

- **정책 가이드라인**: 허용 조건·금지 조건·공정성 보호·개인정보 보호·권리 구제·핵심 원칙 한 문장
- **일관성 점검**(`consistencyQuestions`, 최대 3개):
  - 한 안건에서 B안으로 요구한 보호 조치를, 그 조치가 관련된 다른 안건(A·B)에서는 요구하지 않았을 때. 예: “출입에서는 대체 인증 수단을 요구했는데 채용에서는 왜 요구하지 않았나요?”
  - 출입과 채용 중 한쪽만 도입(A)하고 다른 쪽은 도입하지 않음(C)
  - 치안만 조건 없이 도입(A)
  - 어긋남이 없으면 “세 안건의 판단에 공통으로 적용한 기준” 질문 하나
- **반론 검토**: 기본 반론 또는 교사가 고른 반론(생명 안전·비용·다수결)에 답하고 가이드라인을 유지/수정(수정하면 같은 화면에서 고침)
- **개인 성찰**: 가장 큰 영향 · 유지/변경 이유 · 정확도와 정당성 · 가장 지키고 싶었던 권리(권리 이름 칩으로 넣기)

## 검수가 필요한 문장 (`js/stories.js`의 `draft: true`)

시나리오 원문에 없어 Claude가 채운 초안입니다. 고치거나 그대로 둘 문장은 `draft: false`로 바꿔 주세요.

- 소집 안내(`INTRO`) 4줄 중 3줄, 안건별 심의 도우미 안내(`guideLines`) 각 2줄
- 시뮬레이터 위험 문장·줄어든 위험 문장(`sim.risks`) 12개, 보호 조치별 효율·비용 변화(`protNotes`), C안 효과·위험(`noAdopt`)
- 추가 반론 3개(`REBUTTALS.safety`·`cost`·`majority`) — 시나리오에는 주제(생명 안전·비용·다수결)만 있음
- 안건 3 사고실험 아래 안내 한 줄(`extra.noteDraft`)
- 그 밖에 표시 없이 덧붙인 것: 안건 1 데이터 항목별 설명(`data.options[].note`), 계산 풀이의 “한 달이면 약 3,000명”, 오탐·미탐 설명, 보호 조치 7가지 한 줄 설명(`PROTECTIONS[].desc`), 일관성 점검 질문 문장(`engine.js`)

## 검증

```bash
node --test "humanrights/tests/*.test.mjs"     # 엔진·저장(9개)
PLAYWRIGHT_MODULE=<playwright 경로> node humanrights/tests/play-browser.mjs [스크린샷 폴더]
```

- `engine.test.mjs`: 세 안건→보고서 완주, 최초 판단 잠금, 계산 문항(두 번 시도 후 풀이), 시뮬레이터(A안 위험·전체 조치·C안·관련 없는 조치), 일관성 점검 질문 생성, 손상·옛 저장 복원, 공통 키 읽기 전용·기록 지우기 범위
- `play-browser.mjs`: 헤드리스 Chromium으로 1280px·375px에서 버튼을 실제로 눌러 완주. 공통 팩 그림 로딩, 별명 HTML 이스케이프, 최초 판단 확정 대화 상자, `?rebuttal=majority`, 결과 키 형식, 새로고침 후 이어 하기, 가로 넘침, 404·콘솔 오류 없음

## 남은 확인 사항

- `draft: true` 문장 교사 검토, 어른 역할의 캐릭터 배정
- 실제 학생 플레이 시간(안건 6·12·7분 + 마무리) 측정, 태블릿·휴대폰 실기기 확인
- 공통 팩 런타임이 그림 약 17MB(인물 8명·배경 6장 전체)를 처음에 한꺼번에 불러옴 — 학교 와이파이에서 첫 로딩 시간 확인 필요(그림 없이도 진행은 가능)
- 팀 저장소 `/humanrights/`로 합치는 시점과 방식(합치기 전 확인 필수)
