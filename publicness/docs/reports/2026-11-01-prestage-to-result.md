### 0-2. 「다음에는 누구의 이동을 살필까요?」 선택이 바꾸는 것
**아무것도 바꾸지 않았다.** 미니멀 성찰 화면의 카드 2개는 성찰 쓰기 칸에 카드 문구를 넣을 뿐(`s.reflections[단계]`), 시뮬레이션·AI 제안(`s.goal`은 별도)·점수·엔딩 어디서도 읽지 않았다. 부작용: 카드를 누르면 써 둔 자유 서술이 지워졌다.
→ 지시서대로 **결과 화면 ‘생각해 보기’ 질문의 두 가지 선택형 답**으로 바꾸고 글쓰기는 선택 사항. 고른 답은 `s.choices[단계]`에 따로 저장(자유 서술을 지우지 않음), 다음 단계 지도 HUD에 「이번 목표: 오래 기다린 사람부터」 한 줄. 계산에는 여전히 쓰지 않는다.

## 4. 1단계: 설명문 없이 코치만 보고 첫 노선 만들기
**확인(헤드리스, 학생 직접 플레이는 아님)**: 테스트가 타이틀 → 인트로 → 지도에서 **손가락 표시가 놓인 화면 좌표를 실제 마우스로 두 번 누르기만** 해서 노선 1개(F–D)가 생기고 대기 버스 1대가 자동 운행에 들어가는 것을 확인(기본·랜덤 seed 7 둘 다). 말풍선은 「지도에서 출발할 정류장을 누르세요.」 → 「이어서 갈 정류장을 누르면 노선이 생겨요.」 → 「첫 노선이 생겼어요. 대기 버스가 바로 달려요.」(3초 뒤 닫힘). 모달 없음, 「닫기」로 언제든 닫힘, 도움말 「첫 노선 안내 다시 보기」는 어느 단계든 코치를 다시 띄움. 손가락·말풍선은 지도를 다시 그릴 때마다 자리를 맞춘다(처음엔 지도 틀이 정해지기 전 자리에 있다가 늦게 따라오는 문제를 찾아 고침).

2. 컷 대사 한 줄 새 문구 3개(솔·유나·다은 단체 컷·진호)와 「유나 · 다은」 두 장 → 한 장 합침. 원문은 보존. 문구 검수 필요.
3. 마지막 단계 결과의 선택 질문은 「다음 학기라면 누구의 이동을 먼저 살필까요?」로 바꿔 보여 줌(다음 단계 HUD가 없어서). 고른 답은 기록·팝오버에만.
4. 결과와 잇는 한 줄의 단계별 주제 정류장(`Narrative.THEME`): 1 외곽 / 2 대학교·병원 / 3 신도시 / 4 운동장·터미널 / 5 복지관 / 6 호수공원 / 7 병원·복지관·외곽 / 8 대도시 — 단계 질문 내용에 맞춰 고름.
5. 칩 줄은 좁은 화면에서 한 줄 가로 스크롤(인물 3명이면 390px에서 셋째 칩이 잘려 보임). 두 줄로 접을지 결정 가능.

## 10. 범위 밖 버그·이상(고치지 않음, 목록만)

5. 0단계 조사 7번: 타이틀 「이동 요청 139건」과 결과 「평가 수요 142건」 수치 불일치(손대지 않음).

## 11. 확인 / 미확인
확인(헤드리스 Edge·스크린샷 직접 열람): 1~9절의 항목. 3D(`swiftshader`) 계획·운행·결과는 스모크로 오류 없이 코치·HUD·경로 강조가 동작함을 확인(테스트는 2D 위주).
미확인:
- 실제 학생 플레이(코치만 보고 이해하는지, 체감 시간). 테스트는 손가락 좌표를 정확히 누른 경우만 증명한다.
- 실기기 터치·태블릿·iOS Safari, 실제 GPU 3D에서 경로 깜빡임·작은 지도 성능.
- 스크린리더 실제 낭독(aria-label·aria-live·낭독 사본은 DOM으로만 확인).
- 움직임 줄이기를 끈 상태의 애니메이션 모양(고리·반짝임·깜빡임)은 스크린샷으로 보지 않음(테스트는 움직임 줄이기).
- 저장 이전은 만든 저장본으로만 시험(실제 학생 브라우저에 남은 옛 저장본은 아님).
