# 이번 정류장은… — AI 마을버스 운영단 (`/publicness/`)

중·고등학생이 **AI 자율주행 마을버스를 위탁 운영하는 민간 운영사**가 되어, 한 학기를 나타내는 다섯 단계 동안 노선과 배차를 정하는 공공성 시뮬레이션 게임입니다. 매 단계 운영 목표(수익·이동 시간·소외 지역 연결)를 고르면 **모의 AI**가 계획을 제안하고, 학생은 수락·수정·거절합니다. 결과는 주민의 기다림·도착·환승 기록, 생활권별 불만과 누적 신뢰, 재정으로 돌아옵니다.

> 핵심 질문: 같은 버스로 **누구의 이동을 책임지는가?**

- 대상: 중·고등학생 / 개인 플레이 후 교실 토론 / 목표 20~25분(실측 전)
- 흐름: 시작(사건 세팅 선택) → 단계마다 환경 공개 → 목표·AI 제안 → 노선 편집·출발 → 약 60초 운행(중간 편집·일시정지 없음) → 결과 → … → 결말(주민 이야기 → 운행 기록 → 생각해 보기)
- 3단계에 **신도시**가 갑자기 생기고(그 전에는 지도·글 어디에도 나오지 않음) **4호차**를 들일 수 있습니다.
- 파산·게임오버·실패 판정이 없고, 하나의 도덕 점수로 합치지 않습니다. AI는 악역이 아니라 목표에 맞춰 후보를 비교하는 도구입니다.
- 서버·로그인·외부 AI·분석 도구 없음. 주민과 마을은 모두 허구입니다.
- 기능 정본: `docs/ai-village-bus-prd-v2.md`(PRD v2, 레포에는 올리지 않음).

## 실행

정적 파일입니다. `index.html`을 파일로 직접 열어도(`file://`) 동작합니다(ES 모듈·fetch를 쓰지 않음). 배포 사이트처럼 보려면:

```bash
node publicness/tests/serve.mjs 8080      # → http://127.0.0.1:8080/publicness/
```

- 주소 인자: `?seed=7` 사건 세팅 고정(교사용) · `?no3d=1` 3D 대신 지도로 시작
- WebGL이 안 되는 기기는 자동으로 SVG 지도로 바뀌고 모든 기능이 그대로입니다. 상단의 ‘지도·텍스트 보기’로 언제든 바꿀 수 있습니다.

## 사건 세팅

시작 화면에서 고릅니다.

| 세팅 | seed | 쓰임 |
|---|---|---|
| 기본 세팅 | 42 | 반 전체가 같은 추가 수요·청원을 겪음 → 토론 때 결과 비교 |
| 랜덤 세팅 | 무작위 | 매번 다른 사건 |
| 지정 세팅 | 주소 `?seed=N` | 교사가 정한 사건 |

신도시·기본 수요의 인원과 구간은 세팅과 무관하게 같고, 기본 수요의 발생 시각만 seed에 따라 밀립니다. 결말 화면에 세팅 번호가 표시됩니다.

## 저장 키와 팀 공통 연동

| 키 | 읽기/쓰기 | 내용 |
|---|---|---|
| `ethicity.player` | 읽기만 | 별명(`textContent`로만 표시). 없거나 손상되면 무시 |
| `ethicity.result.publicness` | 결말 도달 시 쓰기 | `{"game":"publicness","completed":true,"ending":null,"card":"이번 정류장은… · 생활권 안정 n · 개선 중 n · 과제 n"}` |

진행 상태는 저장하지 않습니다(PRD: 브라우저 메모리만, 새로고침하면 처음부터 — 시작 화면에 안내). 성찰 응답도 저장·전송하지 않습니다.

## 주요 초기 조정값 (`js/config.js`, 실제 교통·재정 모형 아님)

| 항목 | 값 |
|---|---|
| 버스 | 처음 3대(3단계부터 4호차 선택), 정원 12, 출차 0·4·8·12분 |
| 운행 창 | 120분(화면 약 60초), 요청 0~89분, 정차 1분, 환승 최소 1분 |
| 수요 | 1~2단계 148건, 3~5단계 180건(신도시 32건) |
| 사건 | 단계마다 무사건 60% · 추가 수요(12명) 25% · 청원 15%, 35~60분 |
| 재정(가상원) | 운임 1,000 · 지원금 150,000/단계 · 보유비 20,000/대 · 운행 100/분 · 이동 150/분 |
| 불만·신뢰 | 불만 = 100×(0.5×미완료 + 0.3×대기 15분 초과 + 0.2×경과 30분 초과), 신뢰 = 0.7×이전 + 0.3×(100−불만), 초기 50 |
| 결말 소제목 | 마지막 두 관측 단계 모두 도착률 80%↑·최장 대기 20분↓ → 비교적 안정적 / 첫 관측보다 15%p↑ → 개선이 이어지는 중 / 그 외 남은 이동 과제가 있음 |

값을 바꾸면 `SCENARIO_VERSION`을 올리고 아래 검증을 다시 돌립니다.

## 검수가 필요한 문장 (`js/stories.js`의 `draft: true`)

Claude가 쓴 초안입니다. 고치거나 그대로 둘 문장은 `draft: false`로 바꿔 주세요.

`hook.line1` · `hook.line2` · `hook.line2Served` · `bubbles.noLink` · `bubbles.wait[0]` · `bubbles.wait[1]` · `bubbles.full` · `bubbles.transfer` · `bubbles.arrive` · `residents.jun['jun.waitDropped']` · `residents.jun['jun.steady']` · `residents.any['any.current.arrived']` · `residents.any['any.current.open']` · `closing.riding`

(PRD에 있던 하늘·나래·솔 이야기와 결말 안내 방송 문장은 `draft: false`.)

## 검증

```bash
node --test "publicness/tests/*.test.mjs"   # 엔진·AI·세션·이야기(PRD 인수 기준 1~21)
node publicness/tests/run-probes.mjs        # 헤드리스 Edge 화면 검증 25개 시나리오(키보드 완주·3D·WebGL 실패·접근성·375px 등)
node publicness/tools/sweep.mjs             # 균형 점검(61개 계획) → docs/sweep-<버전>.md
node publicness/tests/shot.mjs <이름> [주소 인자] [폭x높이]   # 스크린샷 → tests/_shot-<이름>.png
```

## 알려진 한계

- 노선은 왕복만 지원합니다(원형 순환 노선 없음). 같은 단계 재실험·수동 일시정지는 없습니다(PRD 첫 구현 제안).
- 승객은 요청 때 정한 여정을 바꾸지 않습니다(만차면 같은 구간의 다음 버스를 기다림).
- 모의 AI는 최적해를 보장하지 않습니다. 예상은 추가 사건 없는 기본 수요 기준입니다.
- 실제 학생 소요 시간(20~25분)·편집 난이도·개념 이해, 실제 태블릿 터치 감각은 아직 확인하지 않았습니다.
