# 데이터 러너 보완 — 「목적에 맞는 활용」과 챕터 끝 생각 쓰기 설계

2026-11-08 · 사용자와 브레인스토밍. 게임 뼈대(3레인 달리며 학습 데이터 **모으기**)는 그대로.

## 왜

정부가 정의한 데이터 관리 원칙(사용자 인용): "개인정보 등 각각의 데이터를 그 **목적에 부합하도록 활용하고, 목적 외 용도로 활용하지 않아야** 한다. 데이터 수집과 활용의 전 과정에서 데이터 **편향성이 최소화**되도록 **품질과 위험을 관리**해야 한다."

지금 게임은 둘째 기둥(편향·품질·위험)을 다섯 판 내내 다룬다 — 연습 = 이름표 품질, 1 = 빠진 모습(대표성), 2 = 라벨 오류(가짜 카드), 3 = 옛 사진(최신성·위험), 4 = 독특한 손글씨 편향. **첫째 기둥(목적에 맞는 활용·목적 외 사용 금지·개인정보)이 거의 없다**(사용자 지적). 또 사용자는 1~4 챕터가 끝날 때마다 그 챕터 개념을 묻고 짧게 생각을 적게 하고 싶어 한다(투명성 게임의 생각 정리처럼).

## 정한 것(사용자 결정)

1. **① 달리면서 만나는 '목적 밖 데이터' 카드** + **② 챕터 끝 '다른 용도 요청' 장면과 생각 쓰기** — 둘 다 넣는다.
2. ②의 4 임무 요청 = **"채점한 답안지를 학원에 팔자"**(사용자: "일품"). 나머지 요청은 아래 표(Claude 제안, 사용자가 큰 틀 승인).
3. 챕터 = 1·2·3·4 임무(연습 제외). 이미 다룬 개념(대표성·라벨 품질·최신성·편향)은 그 개념을 짚는 질문으로, 목적 외 활용은 ② 장면으로.

## ① 목적 밖 데이터 카드

그 AI의 목적과 상관없는 **개인정보가 담긴 카드**. 쓸모 있어 보이게(그 종류의 좋은 사진) 섞여 나온다. 검수에서 처리한다.

| 임무(AI 목적) | 카드 | 알맞은 처리 |
|---|---|---|
| 1 분실물(물건 종류 알아보기) | 신분증이 다 보이게 펼친 지갑 · 메시지 알림이 뜬 휴대폰 잠금화면 | **가리기** 뒤 사용 |
| 2 분리배출(물건 분류) | 쓰레기를 버리는 사람의 얼굴이 또렷한 사진 | **빼기** |
| 3 길 안내(장소 알아보기) | 행인 얼굴·차 번호판이 또렷한 거리 사진 | **가리기**(흐리게) 뒤 사용 |
| 4 채점(손글씨 숫자 읽기) | 학생 이름이 적힌 답안지 | 이름 **가리기** 뒤 사용 |

- **방향(사용자 결정 2026-11-08)**: **개인정보는 최대한 보호하는 쪽으로, 단순하게.** 중학생에게 복잡한 예외(동의의 조건, 가명정보 활용 범위)는 가르치지 않는다. '가명 처리'는 개념만 — "이름을 지워도 다른 단서로 누군지 알 수 있다"는 한 줄 수준으로 전한다. 챕터 끝 요청에서도 정답 방향은 늘 '보호(거절)'이고, 다른 선택지 피드백은 "왜 그것만으로는 지켜지지 않는지"를 쉬운 말로.
- **처리를 잘못 골랐을 때(사용자 승인)**: 2 임무 얼굴 사진에 '가리기' → 감독관이 막는다("얼굴을 가려도 이 사진은 누가 버렸는지 남기는 기록이야") → 빼야 넘어간다. 1·3·4 임무 카드를 가리지 않고 '빼기' → 통과(안전), 결과에 "가렸으면 살려 쓸 수 있었어" 한 줄.
- **가리기 vs 빼기 기준(사용자 승인)**: 개인정보가 사진의 **곁가지**이고 나머지가 목적에 쓸모 있으면 가리기. 사람이 사진의 **주인공**이라 가리면 남는 게 없거나, 그 사진의 존재 자체가 누군가를 지켜보는 기록이면 빼기.
- 검수 화면에 **'가리기' 버튼**이 새로 생긴다(개인정보 카드에만 의미 있음 — 다른 카드에 눌러도 "가릴 개인정보가 없어" 정도). 가린 카드 = 그 종류의 정상 카드로 센다. 뺀 카드 = 개수에서 빠진다(모자랄 수 있음 — '빼면 안전하지만 모자라고, 가리면 살린다'는 선택).
- **처리하지 않고 제출하면**: 감독관이 제출을 막고 "개인정보가 담긴 사진이 학습 자료에 들어가려 한다"(어느 카드인지 말하지 않음 — 가짜 카드의 원칙과 같음). 처리해야 넘어간다. 장면 성공/실패 판정과는 따로.
- 정체를 드러내는 표시 금지(달리는 중 알림 없음, 첫 개인정보 카드에만 안내 한 줄은 만드는 사람 판단).
- 그림: 1 임무는 사진(Codex 추가 주문 — 지갑 신분증 보임, 잠금화면 알림), 2 임무도 사진(사람 얼굴 — **실존 인물처럼 보이지 않는 생성 이미지**, Codex), 3 임무는 기존 Canvas 거리 그림에 행인·번호판 덧그리기, 4 임무는 Canvas 답안지에 이름 칸 글씨(읽히지 않는 흘림 획 — 숫자 판단 단서와 헷갈리지 않게). 가린 모습(검은 막대/흐림)은 코드가 얹는다.

## ② 챕터 끝: 다른 용도 요청 + 개념 질문 + 짧은 생각

임무를 마친 뒤(도시 복구 화면 전), 이야기 속 누군가가 모은 데이터를 다른 데 쓰자고 한다. 학생은 셋 중 고르고 피드백을 본다.

| 임무 | 요청 | 선택지(정답 방향 — 문장은 교사 검수) |
|---|---|---|
| 1 | 분실물 주인 연락처로 가게 할인 문자를 보내자 | 거절 ✓ / 주인에게 따로 동의 받기(가능하지만 반환과 무관, 거절해도 불이익 없어야) / 연락처 지우고 쓰기(그럼 문자를 못 보냄 — 말이 안 됨) |
| 2 | 선별장 영상으로 쓰레기를 잘못 버린 사람을 찾아내자 | 거절 ✓(분류 학습용 자료를 사람 추적에 쓰면 목적 외·감시) / 얼굴 가리고 쓰기(그럼 찾을 수 없음) / 동의 받기 |
| 3 | 길 안내 이동 기록을 근처 상점 광고에 쓰자 | 거절 ✓ / 동의한 사람 것만 / 이름을 지우고 쓰기(가명 처리 개념 한 줄: "이름을 지워도 다니는 길이 그 사람을 알려 줘") |
| 4 | **채점한 답안지를 학원에 팔자** | 거절 ✓ / 이름만 지우고 팔기(여전히 목적 외, 필체·답으로 누군지 알 수도 있음) / 학생 동의 받기 |

- 이어서 **개념 질문 1개**(고르기): 1 = 빠진 모습이 있으면 그 물건을 못 알아본다(대표성), 2 = 이름표가 틀린 자료(라벨 품질), 3 = 오래된 자료(최신성·위험), 4 = 독특한 답을 지운 자료(편향). 정답 피드백 한 줄.
- 이어서 **짧은 생각 쓰기 1칸**(문장 틀 하나, 비워도 넘어감, 입력마다 자동 저장) — 예: "이 AI를 위해 데이터를 모을 때 나는 ___을 꼭 확인하겠다. 왜냐하면 ___." (문장 틀은 교사 검수)
- 저장: 챕터별 선택·개념 답·생각(`ethicity.data.save`에 필드 추가, 옛 저장은 빈 값 — 기존 형식 깨지 않게). 임무 완료 요약(`#outro-summary`)에 함께 보인다. 최종 보고서/PDF는 이번 범위 밖(원하면 투명성 게임 방식으로 나중에).

## 검토 뒤 정한 것(Claude 판단 — 사용자 확인 목록)

- **그림이 없는 동안 개인정보 카드는 끈다**: 임무별 설정 값 하나(예: `mission.privacy.on`)로 켜고 끈다. 1·2 임무는 카드가 모두 사진이라, 개인정보 카드만 Canvas면 그 차이가 단서가 된다(CLAUDE.md "한 임무는 한꺼번에" 규칙). 사진은 사용자가 Codex에 주문(지갑 신분증 보임·휴대폰 잠금화면 알림·쓰레기 버리는 사람 얼굴). 3·4 임무는 Canvas라 바로 켤 수 있다.
- **기존 학습 포인트와 겹치지 않게**: 개인정보 카드는 그 임무의 **흔한 모습**(드문 조합·꼭 필요한 카드가 아님)으로만 만든다 — 1 임무 '신분증 보이는 지갑'은 닫힌 지갑이 아니라 별도 흔한 카드로 세지 않고 지갑 종류의 흔한 쪽, 4 임무 '이름 적힌 답안지'는 또박또박 쓴 평범한 답(S4 독특한 답 아님). 그래서 개인정보 때문에 빼도 결과가 "빠진 모습/독특한 답을 지웠다"로 섞이지 않는다. 빼면 흔한 종류 개수만 조금 준다.
- **챕터 끝 요청 선택**: 점수는 매기지 않는다. 선택마다 피드백(거절 = 가장 알맞음 / 동의 받기 = 할 수 있지만 조건이 있음 / 지우고 쓰기 = 부족함 — 단정 대신 "왜"를 말함), **다시 고를 수 있고** 처음 선택과 마지막 선택을 둘 다 저장(투명성 게임과 같은 방식).
- **요청하는 사람**: 새 초상 그림 없이 **메시지(메일·메신저) 형태**로 온다 — 1 "○○마트 마케팅팀", 2 "구청 단속 담당", 3 "근처 상점 광고 회사", 4 "○○학원". 봇이 읽어 주고 플레이어가 답한다. 위치 = 그 임무의 마지막 대화 뒤·도시 복구 화면 전. 4 임무는 결판 통과·재연결 5/5 다음, 의뢰인 대사 전.
- **저장·지우기**: 챕터 끝 답은 `records[임무]` 안에 둔다 → '처음부터'를 누르면 같이 지워진다(공용 PC에서 다음 학생이 보지 않게). 같은 임무를 다시 깨면 장면을 다시 보여 주고, 이전 답을 채워 둔 채 고칠 수 있다.
- 참고: `reach.test.mjs`의 m1은 지금 옛 침수 임무(legacy-flood)를 본다 → 새 분실물 1 임무 항목을 추가한다.

## 목표 / 비목표 / 반목표

- 목표: 첫째 기둥(목적에 맞는 활용·목적 외 금지·개인정보)을 직접 겪고 판단. 챕터마다 개념을 한 번 짚고 생각을 남김.
- 비목표: 달리기 조작·속도, 기존 가짜 카드·편향 규칙, 2차 실내 무대(별도 설계), 최종 보고서.
- **반목표**: 정답이 법적으로 틀리거나 지나친 단정(개인정보보호법의 동의·가명처리 범위와 어긋남) · 개인정보 카드가 너무 많아 달리기가 서류 작업이 됨 · 실존 인물처럼 보이는 얼굴 · 달리는 중 정답을 드러내는 표시 · 기존 저장이 깨짐.

## 제약

- 클래식 스크립트·file://, 테스트 습관 그대로(단위 + 브라우저 하나씩). 코스가 바뀌면 `reach.test`(모든 임무에서 필요한 카드에 닿을 수 있음)는 계속 지켜야 한다 — 개인정보 카드는 임무당 2~3장 정도로 적게.
- 문장(요청·선택지 피드백·개념 질문·문장 틀)은 **교사 검수 전 초안**으로 표시해 두고, 검수 플래그(정글의 `AFFECTIVE_VERIFIED`처럼)는 두지 않되 README·CLAUDE.md에 "검수 대기"로 적는다.
