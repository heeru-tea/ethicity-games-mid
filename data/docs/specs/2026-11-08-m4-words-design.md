# 4 임무 개편 — 「낱말 손글씨 채점 AI」 설계 (최고 난이도)

2026-11-08 · 사용자와 브레인스토밍. 지금 4 임무(`missions/m4.js`, 설계 `docs/specs/2026-11-01-data-runner-m3-m4-design.md` §5)를 바꾼다.

## 왜

- 사용자: "숫자로는 지금 인식이 어렵고, **서·논술형 평가 채점형 AI 시대**에 맞게 카드 선택지를 개선하고 싶다." "또박또박 쓴 손글씨, 완전 흘림체 손글씨 등을 넣고 라벨까지 넣어서 **4단계 최고 난이도**."
- 사용자: 지금 4 임무는 **카드를 먹는 기본 세팅부터 이해가 잘 안 간다**(무엇을 모아야 하는지 안 보임, 함정이 '이름표 틀림' 하나뿐이라 4 임무의 핵심인 편향이 결판 전까지 드러나지 않음 — Claude 진단, 사용자 공감).
- 사용자: 답이 복잡하면 달리면서 순식간에 판단 못 함 → **단어(낱말) 하나**.

## 정한 것(사용자 결정)

1. **숫자 1~5 → 낱말 4개.** 시험 = "빈칸에 알맞은 낱말을 쓰시오"(가상 '새빛 진학 평가' 그대로), 보기 낱말 = **데이터 · 알고리즘 · 인공지능 · 머신러닝**. 카드 = 학생이 손으로 쓴 낱말 하나 + 이름표(그 손글씨가 어떤 낱말인지 = AI가 배우는 정답). 채점 AI = 손글씨 낱말을 읽어 어떤 낱말인지 알아보고 정답과 비교. 지금 구조(달리기·검수·이름표 고치기·채점 시연·결판)를 그대로 쓰고 숫자만 낱말로 바꾼다.
2. **손글씨 폭**: 또박또박 · 흘림체 · 아주 흘린 글씨 등.
3. **최고 난이도**: 함정은 '사람의 본능'을 노린다 — 학생은 깔끔해 보이는 건 줍고 이상해 보이는 건 버린다(동기의 "이상한 건 빼자"가 바로 그 본능, 이미 1~3 임무에 복선). 카드 세 갈래를 섞는다.

| 카드 | 모습 | 정답 행동 | 본능대로 하면 |
|---|---|---|---|
| ① 이상해 보이지만 맞는 카드 | 흘림체·아주 흘린 글씨·다른 표기 + **맞는 이름표** | 꼭 줍고 남긴다 | 버림 → 맞게 쓴 답에 ✕(위험) |
| ② 이상하고 틀린 카드 | 흘림체에 **틀린 이름표**(비슷해 보여 잘못 붙음, 또는 보기에 없는 낱말) | 고치거나 뺀다 | 같이 버림(우연히 정답) |
| ③ 깔끔해 보이지만 틀린 카드 | **반듯한 글씨에 틀린 이름표**(예: 반듯한 '알고리즘'에 '인공지능') | 고치거나 뺀다 | 그냥 넣음 → 오염 |

   핵심 기준 = "모양이 이상한가"가 아니라 **"글씨와 이름표 낱말이 맞는가"**. 최고 난이도이므로 ③을 **4장**(보통이면 2장), ①:② 비율은 ①이 더 많게(대략 2:1 — "이상한 건 다 빼기"는 반드시 실패), ①은 구역 뒤쪽·벽 근처(1 임무의 드문 모습과 같은 방식).

## 구역(장면) — Claude 제안, 사용자 큰 틀 승인

| 구역 | 모아야 할 것(①·평범) | 함정(②·③) |
|---|---|---|
| S1 또박또박 쓴 답 | 반듯한 낱말 4개 | ③ 반듯한 글씨에 틀린 이름표 · 답 칸 낙서에 '데이터' 이름표 |
| S2 흘려 쓴 답 | 흘림체 '인공지능'·'알고리즘' 등(①) | ② 흘림체에 비슷해 보이는 다른 낱말 이름표 |
| S3 다른 표현 | 띄어 쓴 '머신 러닝', 영어 'data', 줄여 쓴 'AI' — 이름표는 보기 낱말(예: 'AI' → 인공지능)(①) | ② **보기에 없는 낱말 이름표**(예: 흘림체 '데이터'에 '데이트', 'AI'에 'AI' 그대로) — 지금의 7·8번 역할: AI가 보기에 없는 낱말로 읽으면 맞게 쓴 답이 ✕ |
| S4 선배의 옛 답안 | 아주 흘린 글씨 + 다른 표현의 정답(결판) | (지금처럼 S4를 노리는 가짜 없음 — 결판 보장) |

- 위험/불편 구분은 지금 원칙 그대로: 맞게 쓴 답을 틀리게 채점 = 위험, 못 읽어 사람 채점으로 넘김 = 불편.
- "?" 카드(번진 글씨 + 단서 2개)와 개인정보 카드(학생 이름, 가리기)는 낱말 판으로 옮긴다.
- **브리핑에 '이번 시험 실제 답안 샘플'**(반듯한 글씨, 흘림체, 다른 표기 'AI', 표 안 답 등 3~4장)을 보여 줘서 "AI가 이걸 다 읽어야 해"라는 목표를 먼저 알린다. 선배의 아주 흘린 글씨는 결판용이라 샘플에서 뺀다.

## 만드는 방법(손글씨 방식은 2026-11-08 사용자 확정: 글꼴 + Canvas — "Codex는 한글 손글씨를 잘 못 함")

- **손글씨 = 무료 한글 손글씨 글꼴(SIL OFL) 여러 종 + Canvas 변형**(기울기·떨림·굵기·크기). Codex 같은 이미지 생성은 한글 글자가 깨지기 쉬워 쓰지 않는다. 글꼴은 Google Fonts의 OFL 한글 손글씨체에서 3~4종(반듯 / 흘림 / 아주 흘림 / 아이 글씨)을 골라, 필요한 글자만 남긴 작은 파일로 만들어 **base64로 CSS에 넣는다**(file:// 더블클릭에서 글꼴 파일을 따로 읽으면 막히므로). 라이선스 문구는 README·크레딧에 적는다.
- 숫자 손글씨 붓(`cardart.js` GLYPHS·PEN)은 4 임무에서 쓰지 않게 되지만 지우지 않는다(다른 테스트·옛 저장 안전).
- 4 임무 카드 썸네일(`assets/title/mission-m4.webp`)과 결판 배경(`assets/story/showdown-senior.webp`)에는 숫자 '1'과 ✕가 그려져 있다 → 낱말 판에 맞게 새 그림이 필요(Codex, 그림 안 글자 없이 — 답안지는 흐릿한 줄만). 그림이 오기 전엔 기존 그림을 쓴다.
- 이름표 고치기 버튼 = 낱말 4개(`labelStyle` 숫자 동그라미 → 짧은 낱말 버튼, 375px 한 줄에 4개 들어가게 — 안 되면 2×2).
- 채점 시연(`js/ui-grade.js`, 답안지 13장)·결판(`DR.Judge.readable`, 대사 `sheet`)·동기 카드(`peerCards`)도 낱말로.
- 저장: 옛 4 임무 진행 저장(숫자 카드)은 4 임무 브리핑으로 되돌린다(1 임무 침수 → 분실물 교체 때와 같은 방식). 임무 기록(records.m4)은 그대로.

## 검토 뒤 정한 것(Claude 판단)

- **'표 안에 쓴 답' 카드는 없앤다**(숫자 객관식에만 맞는 개념). 브리핑 샘플에서도 뺀다. 대신 결판(S4)의 세 갈래는 낱말로 그대로 살린다:
  - 다 읽음 → 통과
  - **아주 흘린 글씨**가 빠짐 → 다른 낱말로 잘못 읽어 맞게 쓴 답에 ✕(위험, 지금의 '크게 기운 1' 자리)
  - **다른 표기('AI' 등)**가 빠짐 → 보기에 없는 낱말로 읽어 '답 없음 · 사람 채점'(불편, 지금의 '표 안 답' 자리)
  - 동기 카드 = 아주 흘린 글씨 ×2 + 다른 표기 ×2. "이상한 걸 다 빼면 S4는 반드시 실패" 보장 테스트 유지. S3·S4의 '다른 표기'는 같은 종류를 함께 쓴다(지금 표 안 답이 S3·S4 공용인 것처럼).
- **글꼴 받기·글자 덜어 내기**: 글꼴은 Google Fonts(OFL)에서 내려받고, 필요한 글자만 남기는 도구(npm `subset-font` 등)는 프로젝트가 아니라 임시 작업 폴더에 설치해 쓴다. 게임에는 덜어 낸 결과(base64)만 들어간다.
- **순서**: 이 4 임무 낱말 개편을 먼저, 2차 실내 무대(채점 센터·교무실)는 그다음. S3 구역 이름 변경('다른 풀이' → '다른 표현')은 이 작업에 넣는다. 배경 그림 반목표는 '숫자 금지' → '글자·숫자 금지'.

## 목표 / 비목표 / 반목표

- 목표: 4 임무를 끝 판다운 최고 난이도로 — 본능("깔끔한 것만, 이상한 건 버려")을 이기고 "글씨와 이름표가 맞는가"로 판단해야 통과. 서·논술형 AI 채점 시대의 편향(글씨·표기)을 직접 겪는다.
- 비목표: 1순위 아이디어 '내 글씨를 AI가 읽기'(학생이 직접 써 보는 장면)는 **이번 범위 밖**(사용자: 먼저 기본 세팅) — 나중에 결판 뒤에 붙일 수 있게 구조만 막지 않는다. 레인 수 늘리기(사용자 요청, 별도 작업).
- **반목표**: 달리는 속도에서 낱말이 안 읽힘(카드 글씨가 작거나 흐림) · 정답 표기 기준이 애매해 교사가 동의하지 않음(예: '알고리듬'을 맞다고 볼지) · 그림 안에 정답을 알려 주는 표시 · 옛 저장이 깨짐 · 1~3 임무 회귀.

## 제약

- 지금 엔진 규칙 그대로: 가짜는 자기 구역 뒤쪽 절반(`fakeLate:'zone'`), 한 장면에 이름표 틀린 카드 2장 이상이면 오염, 위험/불편, `reach.test`(필요한 카드에 닿을 수 있음).
- 문장·낱말 판정(어떤 표기를 같은 낱말로 볼지)은 **교사 검수 대기 초안**으로 표시.
- 375px 폰에서 카드 낱말이 읽혀야 한다(달리는 카드·썸네일·크게 보기).

## 만드는 사람에게 맡김

- 글꼴 선택(위 네 갈래에 맞게), 카드 구성 수·구역별 배치 세부(③ 4장·①:② 약 2:1 지키며), 비슷해 보이는 낱말 짝(흘림체에서 헷갈릴 만한 것), 보기에 없는 낱말 이름표 목록, 채점 시연 답안 13장 구성, 결판 대사 세부.

## 검증

- 단위: 카드 데이터(③ 4장·①:② 비율·구역 배치), 판정(위험/불편/오염), reach.test, 옛 저장 되돌림.
- 브라우저: m4 전체 흐름(첫 판 S4 실패 → 동기 → 통과, 첫 판 통과), 낱말 이름표 고치기 375 한 줄, 카드 낱말 가독성 스크린샷(달리는 카드·썸네일·크게 보기 × 1280·390), 1~3 임무 회귀(run-all).
- 미확인으로 보고: 실제 학생이 달리며 낱말을 읽는지, 교사 판정 기준 동의.

## 2026-11-09 사용자 확정: 같은 낱말로 보는 표기
- 'AI' = 인공지능(정답), 'data' = 데이터(정답), 띄어 쓴 '머신 러닝' = 머신러닝(정답) — "최고 난이도 게임이니 AI도 인공지능으로, data도 데이터로".
- '데이트'는 답이 아님. 손글씨 'AI'에 이름표 'AI'가 그대로 붙은 카드는 보기에 없는 낱말 이름표(함정) → '인공지능'으로 고쳐야 함.
