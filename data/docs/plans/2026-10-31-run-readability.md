# 달리기 가독성 개선

사용자가 제공한 3단계 명세를 구현한다. 기존 미커밋 변경이 있으므로 현재 작업 디렉터리에서 필요한 부분만 수정한다.

- 1단계: cards.js의 표시색을 범례와 공유. run-feedback.js가 가까운 카드의 선명한 사진, 붙은 라벨, 현재 레인 active 배지, 가방 수집/빈 입력 반응을 담당. run3d.js는 판정 결과만 전달.
- 2단계: 불꽃 실루엣, 빨간 줄무늬 경고, 낮은 반투명 노이즈 띠, 첫 희귀 벽 안내, 피격 이유/가장자리 표시. 판정·거리·HP 변경 없음.
- 3단계: 사용자 승인에 따라 S2(물청소) → S4(고가도로) → S3(밤 번화가) → S1(주택가), 가짜는 같은 라벨 구역에서 코스 50% 이후. mainDeck 장수 비율로 구역 길이를 정하고 보충에서도 같은 지도를 쓴다. night_wet은 S3/S4에 절반씩. counts와 S4 emphasis 유지.
- 검증: 기존 단위 테스트와 flow-browser 기준 실행 → 신규 표시 프로브 → 1280×800/900×800 스크린샷 → 전체 회귀. judge/catch/config/save의 착수 시점 복사본과 비교. 같은 seed의 같은 카드 의미로 결과 비교(구역화로 uid 순서는 달라질 수 있음).

주의: ? 정답·가짜 정체를 글자/색으로 노출하지 않는다. 필요 개수는 supplement && needRevealed에서만 표시. 표시 상태는 save v:1에 넣지 않는다. 가득 찬 가방·다른 레인·늦은 입력·중단 후 재시작·reduced-motion 확인.

## 구현 및 검증 기록

- 진행바 수집 수는 항상 **이번 달리기의 해당 구역 수집 장수**. 보충 때 분모는 장면 combos의 need 합계. 가방 전체의 조합 충족/가짜/판단 필요 분류는 기존 검수·판정이 담당하며 바는 통과 판정이 아니다. 이 구분은 표시의 ‘이번’과 툴팁으로 설명한다.
- 리뷰 수정: 수집 연출을 요소 중심 기준으로 계산해 실제 가방 중심 도착, 빈 입력 상태 만료 및 성공 시 정리, 카드/배지 높이 제한, 보충의 기존 가방/이번 구역 집계 혼용 제거.
- 108개 단위 테스트 통과. seed1101의 수정 전 코스로 만든 4가지 선택 시나리오 결과를 fixtures/readability-1101.json에 보존하여 판정 결과 비교.
- judge.js/catch.js/config.js/save.js SHA256은 착수 시점과 동일. 원본 비교용 임시 복사본은 D:/Works/.data-runner-before-20261031에 보존.
- 1280×800, 900×800 및 667×375 표시 프로브와 스크린샷 확인. 가짜 사진 3종, 판단 필요 3종, 현재 레인 Space, 가방 도착점, 빈 입력 정리, 위험 경고/HP, 구역 표지/진행바, 필요 개수 조건 확인.
- 실제 학생 플레이 손맛·실기기 성능은 미확인. 배포하지 않음.
- 최종 전체 브라우저 회귀 13/13 통과: 브리핑 → 달리기 → 검수 → 결과 → 보충 → 재제출, 새로고침 이어하기/저장, 키보드·터치, 불꽃, 구역 표시 포함. git diff --check 오류 없음.
