# 계획 — 보충 달리기 누적 목표 · 동기 자리 안내 · 4 임무 같은 답안지 전후 비교 (2026-11-09)

요청서: `docs/feedback/2026-11-09-m4-supplement-compare.md`(교사 피드백, 원문 그대로). 판정 규칙·코스·카드 수·저장 키 구조·4레인·실내 무대는 그대로.

## 판단(Ruling)
- **R1 모든 임무의 보충 달리기에 같은 표시**(공용 `run-feedback`). 이유: 보충 달리기는 늘 첫 결과 뒤라 1 임무 `hideShapes`(첫 결과 전까지 모습 이름 숨김)와 겹치지 않고, 2·3 임무도 같은 문제(이미 찬 자료를 더 모음)가 있다. 튜토리얼은 보충이 없고 자기 목표(`runGoal`)가 그대로.
- **R2 어느 줄을 "모자람"으로 보나** = 출발할 때 가방 + 동기 카드로 판정(`DR.Judge.judge`)해서 빠진 조합. 보충 준비가 이미 같은 판정으로 "다시 제출 / 출발"을 정하므로 새로 드러나는 정보가 없다. 같은 종류 묶음(예: S1·S3 또박또박, S3·S4 띄어 쓴 '머신 러닝')은 한 줄(필요 장수 = 큰 쪽).
- **R3 개수는 화면 규칙 그대로**(`DR.Cards.labelCounts` = 검수·보충 준비·결과의 "붙은 이름표 기준"). 가짜의 정체·"?" 카드 정답을 드러내지 않는다. 달리며 잡은 "?" 카드는 세지 않고 "검수에서 정하기"로 따로. 결과적으로 이름표가 틀린 카드는 검수 화면과 같은 줄로 센다(검수 화면과 같은 정보, 더 이르게 보일 뿐) — 교사 확인 항목.
- **R4 이미 찬 자료** = 모자란 줄 뒤에 흐리게 "✓ 이름"(넓은 화면), 좁은 화면은 "다 찬 자료 n개는 더 안 담아도 돼요" 한 줄.
- **R5 동기 자리**: 결판 뒤 보충에 동기 카드(`peerCards` 합 4장)가 예약될 때만 — 달리기 가방 옆 `동기 자리 4칸`, 보충 준비에 "가방 4칸은 동기가 가져올 답안 자리예요" + 가방 칸 셈 한 줄.
- **R6 전후 비교(4 임무)**: 첫 판정 때 채점 시연 결과(답안지마다 도장·원인)와 첫 가방(최소 필드)을 `state.firstGrade`로(저장 선택 필드, 옛 저장은 없음 → 표 없음). 임무 완료 화면에 결과가 바뀐 답안지 최대 3장 + 그대로 맞은 답안지 1장(비교용). 첫 제출에 모두 맞았으면 짧은 한 줄. 사람의 판단 한 줄.
