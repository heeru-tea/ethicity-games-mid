# 공유한 순간 — 프라이버시 선택 게임 (`/privacy/`)

중·고등학생이 학급 축제를 준비하는 나흘 동안 단톡방·SNS·AI 도우미·공용 PC에서 마주치는 프라이버시 문제를 **선택의 누적**으로 경험하는 웹 게임입니다. 정답·오답을 표시하지 않고, 앞선 선택이 뒤의 대화·선택지·결말로 돌아옵니다.

> 핵심 질문: 누가, 누구의 정보를, 누구에게, 어떤 목적으로, 어디까지 공유할 수 있는가?

- 대상: 중학생·고등학생 / 개인 플레이 후 교실 토론 / 첫 플레이 약 15~20분(목표치, 실측 전)
- 구성: 프롤로그 → 1~3장(사건 9개) → 에필로그 → 엔딩 → 선택 경로 → 성찰 질문
- **처음부터 끝까지 맵 위에서** 진행한다(포켓몬식). 아침에 내 방에서 일어나 교실까지 걸어가는 **등교 오프닝**으로 시작하고, 사건 사이에는 다음 장소(❗)까지 걷는다. 하교·귀가는 교문 → 마을 길 → 우리 집까지 직접 걷는다.
- 모든 장면은 맵 위 한 장소에서 벌어진다. 단톡·개인톡·SNS는 **폰**, 공용 PC·AI 도우미는 **모니터**로 그 장소 위에 떠오르고, 그 자리 대화는 아래 **대화창**에 한 줄씩 나온다. 같은 공간 친구는 머리 위 말풍선으로 반응한다(폰 메시지는 원문 대신 📱…). 넓은 화면에선 시선 순서대로 카톡(폰)이 왼쪽, 내 응답(선택)이 오른쪽.
- 엔딩에 처음 도착하면 **검은 화면 연출**(프로스트펑크식): “게임이 끝났습니다.” “과연 당신의 선택은 어떠했을까요?” → 9개 사건에서 고른 선택 → 친구 얼굴과 믿음이 생김·그대로·줄어듦 → 엔딩 이름·결과 보기. 누르거나 Enter면 한꺼번에, 건너뛰기·Esc로 닫기.
- 소리는 기본으로 꺼져 있고, 메뉴의 **효과음(메시지 수신음)**을 켜면 메시지 하나당 짧은 “띠링”(파일 없이 합성).
- 서버·로그인·외부 API·분석 도구 없음. 게임 속 이름·번호·계좌·학교는 모두 허구.

## 실행

정적 파일이므로 아무 정적 서버로 저장소 루트를 열고 `/privacy/`에 접속합니다.

```bash
node privacy/tests/serve.mjs 8080      # → http://127.0.0.1:8080/privacy/
```

`index.html`을 파일로 직접 열어도(`file://`) 실행됩니다(ES 모듈을 쓰지 않음). 다만 `file://`에서는 브라우저에 따라 저장이 막힐 수 있고, 그때는 메모리로만 진행하며 안내가 뜹니다.

## 저장 키와 팀 공통 연동

| 키 | 읽기/쓰기 | 내용 |
|---|---|---|
| `ethicity.player` | **읽기만** | `{"character":"char_03","nickname":"…"}` — 없음·손상·형식 오류면 기본 아바타 + ‘플레이어’. 절대 덮어쓰지 않음 |
| `ethicity.result.privacy` | 엔딩 도달 시 쓰기 | `{"game":"privacy","completed":true,"ending":"B","card":"…"}` — 다시 완료하면 최근 결과로 갱신, 재시작만으로는 지우지 않음 |
| `ethicity.privacy.progress.v1` | 이 게임 전용 | `{ v:1, run:{현재 장면·상태·선택 기록}, explored:{장면:[고른 선택지]}, endingsSeen:[…] }` |
| `ethicity.privacy.settings.v1` | 이 게임 전용 | 대사 속도·움직임 줄이기 |
| `ethicity.privacy.card.v1` | 이 게임 전용 | 성찰 카드에 쓴 글·이름·학번(이 기기에만, 2026-11-10) — 기록 지우기·새 진행 시작 때 함께 지움 |

- **`card` 임시 가정**: 저장소에 `card`의 팀 공통 정의가 없어서(2026-10-17 확인) 결과 요약 문자열을 넣습니다. 예: `공유한 순간 · 엔딩 B 「멈춘 확산, 남은 과제」 — 문제가 생겼지만, 확산을 줄이고 회복을 시작했다.` 공통 형식이 정해지면 `js/app.js`의 `cardText()`만 바꾸면 됩니다.
- **공통 캐릭터 이미지**: 저장소에 공통 캐릭터 이미지·매핑이 아직 없습니다. 정해지면 `js/config.js`의 `characterImages`에 `'char_03': '../경로/char_03.png'` 형태로 추가합니다. 매핑이 없는 코드는 임시 아바타로 표시하고 대체 텍스트도 ‘임시 아바타’로 둡니다.
- 별명은 항상 `textContent`로만 표시합니다(HTML로 해석하지 않음).
- 메뉴의 ‘이 게임 기록 지우기’는 `ethicity.privacy.progress.v1`·`ethicity.result.privacy`와 성찰 카드(`ethicity.privacy.card.v1`)만 지웁니다. 공통 플레이어 정보와 다른 게임 키는 건드리지 않습니다.
- localStorage는 **같은 출처(origin)** 안에서만 공유됩니다. 다른 게임과 결과를 공유하려면 같은 도메인에 배포해야 합니다. 출처 간 전송 기능은 넣지 않았습니다.

### 엔딩 판정 (위에서부터 처음 맞는 하나)

| 코드 | 제목 | 조건 |
|---|---|---|
| D | 혼자서는 풀리지 않는 일 | 사건 8 영상 확산 뒤 수습·도움을 끝까지 사양해 위험이 남음 **또는** 현실의 안전 위협 상황 3회 이상 (약속 장소에 나간 것만으로는 D가 아님) |
| A | 함께 세운 경계 | 필요 이상 확산 ≤ 2 **그리고** 필요한 범위만 공유 ≥ 2 **그리고** 내가 해친 친구 0명 **그리고** 당사자의 뜻을 무시한 행동 없음 (2026-11-13 — 물어본 횟수는 조건이 아님) |
| B | 멈춘 확산, 남은 과제 | 수습 행동 + 도움 연결 ≥ 3 **그리고** 필요 이상 확산 ≤ 4 **그리고** 내가 해친 친구 2명 이하 |
| C | 삭제 이후에도 | 그 밖의 모든 경우(기본값) |

- "내가 해친 친구"(`harm_count`, `js/engine.js`)는 사진·번호·캡처·가짜 영상·계정으로 그 친구에게 피해를 준 적이 있는지를 친구별로 센 수(0~4)입니다. 2026-11-10 플레이테스트에서 나쁜 선택을 여럿 하고 수습만 해도 B가 나와 조건을 좁혔습니다(실수 한두 번 뒤 잘 수습하면 B).
- 내가 해친 친구의 믿음은 처음(0)보다 올라가지 않습니다 — 올린 사진을 지워 줬다고 믿음이 생기지는 않게(`engine.js` `capTrust`).
- "당사자의 뜻을 무시한 행동"(`overrode_wish`, `js/engine.js`)은 거절·비밀·삭제 요청을 어기거나, 허락이 필요한 촬영·공유·계정 사용을 묻지 않고 **실제로 한** 선택입니다. 묻지 않았다는 것만으로는 해당하지 않습니다(안 찍기·안 올리기·필요한 것만 전하기). 목록은 아래 「엔딩 A 기준 — 당사자의 뜻을 무시한 행동(2026-11-13)」. 물어본 횟수(`consent`)는 결과 지표에 그대로 남고 엔딩 A 문장을 고르는 데만 씁니다.

수치(`spread`·`consent`·`minimize`·`repair`·`help`·`serious`, 인물별 신뢰)는 하나의 점수·등급으로 합치지 않습니다. 장 전환·엔딩 화면에는 항목별 변화량·횟수와 인물별 신뢰(믿음이 생김·그대로·줄어듦), 사건별 결과 문장으로만 보여 줍니다. 엔딩 화면에는 “엔딩은 성격이나 등급이 아니다”라는 안내가 붙습니다.

- 첫날 아침은 내 방에서 시작해 직접 등교(오프닝). 이후 다음 날 아침은 ‘다음 날’ 카드 뒤 **교문 앞**에서 시작, 하교는 직접 걷기. 모든 걷기 구간은 시작 위치(spawn)가 정해져 있다.

| 오프닝(등교) | 내 방 → 교실 | 하윤(반 친구 소개) |

| ② 잠든 사진 | 교실 | 민준(엎드려 잠듦) |

| ④ AI 가짜 춤 영상 | 매점 앞 | 도현 |
| ⑤ AI 도우미 | 내 방 | 내 책상 컴퓨터 |
| ⑥ 공용 PC | 도서관 | 공용 PC 3번 |

- 조작: 방향키·WASD 이동, Space·Enter 말 걸기·조사 / 화면을 누르면 그 칸까지 걸어감(인물·사물을 누르면 가서 말 걸기) / **‘목적지로 바로 가기’** 버튼(걷기가 어려운 학생·시간 부족 대비).

## 엔딩 A 회복 경로 (2026-11-14, 교사 검수 대기)

교사 요청: 해친 친구 기록(`harm_count`)·뜻을 무시한 행동 기록(`overrode_wish`)은 지워지지 않아서, 초반에 한 번 실수하고 그 일을 제대로 수습해도 A에 닿을 수 없었습니다. **예방 A는 그대로 두고, '실수한 사건이 하나뿐이고 그 사건에 맞는 수습을 끝까지 한' 경로도 A(회복 A)로 봅니다.** 숫자 기준(확산 ≤2 · 최소 공유 ≥2)은 바꾸지 않았고, 피해 기록·믿음 상한도 그대로입니다.

- A 조건(`js/story.js`): `spread<=2 && minimize>=2 && harm_count=0 && !overrode_wish`(예방 A) `|| spread<=2 && minimize>=2 && recovered`(회복 A). D가 먼저인 순서와 B·C·D는 그대로.
- `recovered`(`js/engine.js` COMPUTED) = 회복할 수 있는 실수를 한 사건이 **정확히 하나** + **그 사건의** 수습 완료 + 회복할 수 없는 일 없음. 다른 사건의 수습·도움 점수로 대신할 수 없습니다.

| 사건 | 회복할 수 있는 실수(`slip.*`) | 그 사건에 맞는 수습(`fix.*`) | 부족하거나 거절 |

| 2 잠든 민준이 | 묻지 않고 찍음(반 단톡방까지 올린 경우 포함) | 내리고, 저장한 사람에게도 지워 달라고 부탁(`all`) | 내리고 사과만(`sorry` — 사본 회수 요청 없음) · 삭제 요청 넘김(`no`) · 올리기 전에 물어 안 올림(`ask` — 찍은 사진을 지우는 선택이 게임에 없어 수습 완료로 치지 않음) |

**회복 A로 올라갈 수 없는 일**(`grave_harm`) — 수습을 해도 B까지입니다.

같은 친구라도 사건이 둘이면 실수 둘로 셉니다. 예: 민준 사진 + 번호 방관 → 해친 친구는 1명이지만 회복 A가 아닙니다.
